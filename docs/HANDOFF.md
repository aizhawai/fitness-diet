## 四、踩过的坑与根因（这部分最有价值）

### 1. 🔴 白屏：Vite dev server 不失效旧进程

**症状**：页面完全白屏，`TypeError: Cannot assign to read only property '_'`。

**根因**：我改 Vue 版本后没重启 dev server。**Vite 默认不 watch `node_modules`**，旧进程继续从内存 transform 缓存里发旧版 `@vue/shared`（3.5.44），而 uni 运行时是 3.4.21 → 混版 → Vue 的 `initSlots` 把 `_` 定义为 non-writable，随后 `normalizeChildren` 又要写 `children._` → 抛错 → 渲染中断。

**定位方法**（可复用）：把坏掉的和正常的两个 server 所有模块抓下来逐字节 diff，找到唯一差异；再反向验证——把 alias 指向坏版本立刻复现。

**已加固**：`package.json` 加 `predev:h5` 清 `node_modules/.vite`。

> **纪律：改任何依赖版本 + `npm install` 之后，必须重启 dev server。**

### 2. better-sqlite3 在 Node 24 装不上

无预编译包 → 回退源码编译 → 缺 Visual Studio → 失败。
**解法**：改用 Node 24 内置 `node:sqlite`（SQLite 3.51.3），零原生依赖。

> ⚠️ 注意它的两个特性：不能绑定 `undefined`（可空字段必须显式传 `null`）；返回行是 null-prototype 对象（测试用 `toEqual` 不能用 `toStrictEqual`）。

### 3. uni-app 的 Vue 版本必须钉死

`@dcloudio/*` 全部**精确**依赖 `3.4.21`（compiler-sfc / compiler-dom / shared / runtime-core…）。
`vue` 若写成 `^3.4.21` 会解析到 3.5.44，直接版本撕裂。
**已在 `client/package.json` 用 `overrides` 把整条 @vue/* 树钉在 3.4.21。**

### 4. 沙箱权限边界

| 被拦的操作 | 绕行方式 |
|---|---|
| `npx degit` 拉官方模板 | 手写 uni-app 工程 + 固定版本 |
| `npm install`（部分） | 用户手动 `! npm install` |
| `taskkill` 非本会话进程 | 改用别的端口（`PORT=3001`） |
| 写 `/tmp` 下的固定路径 | 改用项目内路径或管道 |
| 写共享的 `server/data/app.db` | 用 `DATA_DIR` 环境变量指向临时目录 |

### 5. 内存吃紧，进程被系统回收

同时跑「后端 + 前端 dev server + 浏览器」会被 OOM killer 干掉。
**并行开发时一次只起一个进程，验证完立刻关。**

## 五、算法上的三个关键决定（planner）

1. **蛋白槽永不跳过**。极低热量目标时，宁可让整餐超出 `kcalMax` 并标 `degraded`，也不接受「缺蛋白却标达标」的假达标——用户减的正是蛋白，自欺欺人。

2. **额外主食槽排在最后**。大餐次（16-8 / 高热量）会按 `LARGE_MEAL_KCAL` 追加主食槽，但**必须排在最后**：若插在蛋白前面，贪心会先吃两道主食再硬塞蛋白，把整餐顶出上限。

3. **`LARGE_MEAL_KCAL` 从 780 降到 500**。原值下 `moderate` 档（2264 kcal）早餐目标 679，7 天里 6 天**误标 degraded**——根因是早餐候选池浅（蔬菜只有 10 道），多样性降权把高热量候选压下去后剩余组合够不到 `kcalMin`，被迫走 simple 兜底。降到 500 后 7 天全达标零降级。

> 相关：改 planner 后**必须**跑 `npx tsx scripts/planner-smoke.ts`（各热量档位 + 7 天重复检查）和 `scripts/breakfast-repro.ts`。

## 九、核心设计不变式（改动时别破坏）

1. **`core/` 必须是纯函数** —— 不 import db / fs / 网络 / fastify，菜谱与历史一律以参数传入
2. **AI 只输出结构化 JSON（菜名 + 配料），营养数字一律后端算** —— AI schema 里不许有营养字段
3. **产品永远可用** —— AI 挂了静默降级纯算法；算法凑不出达标组合时用纯食材项兜底并如实标 `degraded`
4. **宁可如实报降级，不做假达标**
5. **确定性** —— 同输入必须同输出，不用 `Math.random()`，用输入 id 的稳定哈希做 tie-break
